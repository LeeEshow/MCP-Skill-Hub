# Layer 1 Principle — Code Style

本文件定義專案內程式碼撰寫風格與品質約束，所有新增/修改程式碼皆須符合。

代號格式：未標＝核心（偏離須讓審查者查得到原因，見 AIC-12）；`[建議]`＝偏離無須說明；`[前提:…]`＝符合前提才適用。

---

## 一、 命名規範 (Naming Conventions)

- STY-01 命名優先遵循技術棧官方指南與專案既有慣例；預設型別/類別用 PascalCase，變數/參數/欄位用 camelCase。
- STY-02 名稱須自我解釋，使用完整單字，避免隨意縮寫；`id`、`url`、`api`、`dto`、`db` 與業界標準縮寫、領域術語不在此限。

---

## 二、 函式與控制流設計 (Function & Control Flow)

- STY-03 `[建議]` 方法單一職責、可一眼讀懂；長度、參數數量、巢狀深度過大視為重構訊號（參考值：30 邏輯行、4 參數、3 層巢狀）。
- STY-04 `[建議]` 參數過多時改用具名參數物件；避免以布林參數切換行為分支。

---

## 三、 程式碼品質與整潔 (Code Quality)

- STY-07 具業務意義的數值與字串設定值須具名，不散落為魔術數字（`0`、`1`、`-1` 除外）。
- STY-08 禁止無用程式碼殘留：未使用變數、匯入、無效方法、被註解掉的程式碼。

---

## 四、 註解規範 (Comments)

- STY-10 預設不寫註解；只寫讀者無法從程式碼推導的「為什麼」（隱藏約束或不變式、安全防線、外部系統繞道寫法），不描述語法或行為。
- STY-14 註解不標註 Task ID 與修改歷程（應歸 Git Log）；程式碼變更時關聯註解須同步更新。
