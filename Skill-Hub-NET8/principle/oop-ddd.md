# Layer 1 Principle — OOP & Domain Design

- OOP-01 每個類別與模組僅限單一職責（單一改變理由），避免跨層級的直接依賴。
- OOP-03 跨模組依賴須能被替換或隔離；有替換、測試或隔離需求時以介面抽象，單一實作且無此需求者不強制建立介面。
- OOP-04 不從類別外部直接修改其內部狀態，狀態變更經公開方法。
- OOP-05 具備多重屬性的複合值（如金額與幣別、起訖時間）設計為不可變物件。
- OOP-06 依賴方向單一：核心業務邏輯不依賴 UI 或外部 I/O 細節（資料庫、框架、外部服務），也不洩漏到展示層或資料存取層；有 Domain 層的專案以 Domain 為核心。
