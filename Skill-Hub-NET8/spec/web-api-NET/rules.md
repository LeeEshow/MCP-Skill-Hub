# Layer 2 Rules — web-api-NET Spec

代號格式：未標＝核心（偏離須讓審查者查得到原因，見 AIC-12）；`[建議]`＝偏離無須說明；`[前提:…]`＝符合前提才適用。

- API-01 分層與資料存取細節依專案實際有無 Domain 層或資料庫取捨（Domain 型、Gateway／代理型、整合型、BFF 皆適用本 Spec）。
- API-06 內部實體與持久化模型不直接序列化對外；對外契約型別（Request／Response）獨立定義，不含業務邏輯與持久化標記。
- API-09 Controller 只做協定轉接（接收請求、驗證、呼叫服務、回傳），業務邏輯與資料存取不放在 Controller。
- API-10 協定風格（RPC 型 POST 或 REST 動詞語意）於專案或端點類別內一致，並於專案文件聲明。
- API-11 回應格式於專案內一致，成功與否、資料、錯誤訊息可辨識；錯誤以狀態碼區分且 Body 不為空、不洩漏內部細節；專案使用的狀態碼須有文件說明。
- API-13 Singleton 不得持有 Scoped 依賴。
- API-14 輸入驗證在進入業務邏輯前，於一致的集中位置完成（如 DTO、Filter、Validator），不散落於各 Action。
- API-15 生產環境對外暴露的 API 文件與維運端點，須是有意識的控管決定（網路隔離或存取控制），並聲明暴露範圍。
- API-16 對外 API 須有可由程式碼產生的說明文件，含可能回傳的狀態碼；產生手段自選。
