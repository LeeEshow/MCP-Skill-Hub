# ui-token 完整規範

本版只說明每條規則的意圖、原因與合格／不合格的判斷界線，不提供程式碼範例，也不指定唯一做法；Token 的檔案結構、命名與分層由專案自選，達成意圖即合格。

## UIT-01 元件引用具語意的 Token
- 意圖：元件使用有語意的 Token，互動狀態色也由 Token 表達。
- 為什麼：元件直接寫原始值或用濾鏡調色，會讓全站視覺調整與主題切換無法集中處理。
- 合格：元件引用語意層或用途命名的 Token；hover、active、disabled 狀態有對應 Token；Token 分一層或兩層皆可。
- 不合格：元件直接寫色碼；以 `filter` 或魔術色值臨時調整互動狀態。

## UIT-02 設計數值集中管理
- 意圖：顏色、尺寸、字體、陰影、層級都由集中定義的 Token 提供。
- 為什麼：數值散落在元件內，改一處需要全專案搜尋，也容易出現近似但不一致的值。
- 合格：數值定義在集中的 Token 檔（單檔或多檔皆可），元件與內聯樣式不寫字面值；Token 定義檔本身除外；命名格式與級距自訂。
- 不合格：元件 CSS 或內聯樣式出現硬編碼的色碼、px 尺寸、z-index 數字。

## UIT-06 主題切換在 Token 層
- 意圖：若支援主題切換，切換發生在 Token 層。
- 為什麼：每個元件各自判斷主題會重複且容易漏改。
- 合格：以選擇器或變數覆寫語意 Token，元件不感知主題。
- 不合格：元件內各自撰寫深淺色判斷。

## UIT-11 不建立語意重複的 Token
- 意圖：新增前先確認有無可複用的既有 Token。
- 為什麼：語意重複的 Token 會在調整時只改到其中一個，造成不一致。
- 合格：新需求先查既有 Token，確實沒有才新增。
- 不合格：同時存在兩個用途相同、名稱不同的 Token。
